# 项目持久化与视频上下文补充方案独立审核

## 裁定

1. `PHASE-12-PROJECT-PERSISTENCE-DESIGN.md`：**有条件通过**。统一项目/owner/门/幂等快照、持久真源恢复、生产不注入黄金项目，已回应前轮A项架构阻塞。下列P1-P5先冻结契约后实施；不是项目持久化实现已验收。
2. `PHASE-12-VIDEO-CONTEXT-DESIGN.md`：**有条件通过，可以按V1-V4实施最小选择器**。不需自动创建节点或平行画布体系；不能把已有合法HTTP上下文的浏览器通过称为普通创建分集路径通过。

## 项目持久化Required

**P1｜ID契约冲突先解决。**方案使用提交前UUID；`docs/contracts/ASSET-REGISTRY-INTERFACE-CATALOG.yaml:11`目前仍规定确定性递增、禁止UUID/随机，范围列出project_id/gate_id。二者不能同时声称遵循。先明确批准并修订项目/门的ID例外契约，或采用独立持久化的单调ID预留，在发布失败/重启后不回收序号。不可只在失败事务中递增随后回滚，造成孤儿视频ACL的ID重用。

**P2｜权限与兼容不能留空。**冻结admin/governor是否可直接操作门、owner之外grant的可信来源、无权响应403或404的唯一规则；如果本轮只做owner+治理角色，明确不宣称通用成员系统已实现。项目列表若保留共享语义，其门/owner/grant/幂等记录不得随项目对象无条件序列化暴露；门发现和详情须逐项目按权限过滤，registry快照也不能泄露历史门。原项目编辑/归档共享语义是否改变须明文说明，不能借新增门暗中扩大或收紧所有项目权限。

**P3｜门状态和幂等精确定义。**冻结同态PATCH是否升门版本、approved撤回的权限/说明要求、非法转换错误、expected_version缺失和陈旧响应。创建幂等摘要包含规范化门输入；请求重试先按主体/键验证摘要再返回原项目，不重新运行绑定/建门。幂等冲突和请求数量、字符串长度上限都有回归。

**P4｜跨库发布边界。**ACL先绑定、projects后原子发布可接受，但所有视频新建/授权/恢复执行路径均须以项目真源存在为前提，不能只在HTTP创建时查一次后让孤儿queued任务在重启自动执行。孤儿ACL不可授权操作，不能自动被当前用户认领或被新项目复用。项目快照成功才向前端可见，失败/损坏不能回退黄金种子或空库。此方案只保证单实例，不声称跨库ACID或多worker一致性。

**P5｜迁移与验收。**不按名称猜测旧内存项目/owner。若切换时还有需要保留的运行期项目，先明确人工导出/迁移范围，不能隐式丢弃或凭无证据绑定恢复。项目字段、owner、门版本/状态、创建幂等、归档回收恢复必须全进程重启读回。真实HTTP+浏览器验证门来源；域锁屏障验证门更新与归档竞争；测试用例显式内存模式不等于生产持久模式已通过。

## 视频选择器Required

**V1｜偏好隔离与失效。**本地偏好按稳定主体、project_id、pipeline_id分区；缺少稳定主体时不要复用其他账号旧偏好。切项目/流水线/身份必须丢弃不匹配选择；空值、已删除实体或无权画布应明确失效并禁用，不静默选第一个节点。生产上下文为初始值，覆盖只来自用户明确选择。

**V2｜异步响应不能写错选择。**画布列表、拓扑请求携带当前项目/流水线/选择代次；切换后Abort或丢弃迟到响应。生成前重新读回当前画布归属与实体，后端仍是最终授权真源。无候选应提供明确下一步入口，而非隐藏错误或自动建节点。

**V3｜与原幂等请求隔离。**上下文改选只影响下一次新请求。已有submitting/未知提交结果保留原key+原payload并按原关联恢复；不能用原key提交新上下文，也不能在改选后自动新建收费任务。已有job_id/asset_id的历史归属不改写；导出只能选择后端授权的同项目素材，新导出关联用明确当前选择。

**V4｜验收边界。**普通UI创建无production_context分集→初始禁用→实际选择真实画布/节点→明确点击生成→metadata播放/下载字节→本地导出→刷新偏好；补切换项目/流水线/身份、迟到拓扑响应、已删实体后端拒绝、未知结果重试仍原payload、无自动收费创建。测试使用本地回环Provider，不能声称真实商业Provider验收。

## 范围

这两项是补足已确认业务目标的设计裁定，不批准发布或缩减“除画布全部真实接入”目标。画布本身仍走god-canvas冻结接口，不引入旧仓实现。新增/修订契约需与实际选定方案一致后再实施。
