- 日期：2026-09-27。
- 用户明确授权：**“将视频渲染/导出、团队消息、Provider tokens/s 三项都纳入本轮新增实现”**。
- 此授权取代本轮滚动记录中的“三项范围待裁定”；不改变公开发布、外部第三方审计、旧仓禁止读取、二进制禁入仓、单实例部署边界。
- 本文件为待技术审核方案，不把计划当作实现，不宣告阶段完成。

## 一、实施顺序与职责

1. 完成安全探针与真实登录浏览器验证工具；各自产物独占，最多两名子代理同时运行。
2. 技术架构负责人依据当前洁净室契约与自有实现细化下述契约、状态/权限/故障模型；GPT-6-Astra high 在实施前审核范围忠实性与安全约束。
3. 实施负责人使用 GPT-6-luna max，按团队消息 → Provider 吞吐 → 视频生成/渲染与导出逐块落实，尽量串行；只在文件所有权明确且互不依赖时并行两个。
4. 集成后全量 pytest、合法夹具安全探针、JS 守卫、真实认证浏览器；独立审核 Required 清零后才可作最终判定。

## 二、视频能力：必须覆盖现有业务，不以本地占位替代

当前 `episode-pipeline.js::generateVideo` 用 prompt、provider_id、model、duration、aspect_ratio 和 production_context 创建视频任务，然后轮询状态并消费视频 URL/asset_id。因此不能只增加一个本地 FFmpeg 命令就冒称现有视频生成流程已接通。

- 保留 `/api/video-tasks` 的现有前端调用入口；统一权威 `job_id`、`poll_hint`，采用真实异步任务与持久化状态。
- 支持配置驱动的真实上游视频创建/轮询/结果取回；仅实现有官方或配置协议证据的适配器，缺凭据/协议不支持/依赖不可用时明确失败关闭。
- 增加真实本地渲染/导出：基于已授权访问的实际媒体输入使用 FFmpeg，生成可由 ffprobe 校验的输出。输出放数据目录或用户选择的授权目录，不进仓库。
- 必须有 accepted/queued/running/succeeded/failed/canceled/interrupted 等明确状态转换（最终用冻结契约统一），终态不可被晚到结果覆盖；不以时间推测进度，不预先生成成功URL。
- 作业输入归属、项目/用户权限、允许根路径、安全出网、远端重定向与凭据隔离、超时、取消、重启恢复/中断、并发限制、幂等键、产物下载权限均需契约与测试。
- 前端真实提交、轮询、终态错误、取消、成功视频预览/下载及导出可达；离页取消轮询，不能因前端未轮询而让任务丢失。
- 验证：临时生成测试媒体，跑真实 FFmpeg/ffprobe；上游协议使用受控 HTTP 服务验证，但不得将桩当作当前真实商业 Provider 已验收。

## 三、团队消息：权限与重启持久性是必需项

- 建议复用团队管理命名空间 `/api/asset-auth/teams/{team_id}/messages`，提供发送、历史分页/增量读取；不另建平行身份体系。
- 作者身份只能来自服务端认证上下文，客户端不得伪造作者、角色或团队成员资格。
- 团队成员及治理角色的读写权限分别冻结；跨团队越权、移除成员、只读角色、未登录均须失败关闭。
- 消息有稳定 message_id、服务端时间和确定性排序；重试幂等、长度限制、空白拒绝、XSS安全渲染、分页不丢不重。
- **当前 auth_management 是进程内状态**：不能只持久化消息而让团队/成员重启后丢失。最小必要团队/成员/身份引用持久化及旧内存模式兼容必须纳入方案，不持久化临时Bearer凭据。
- collab 页团队选择、历史、真实发送、错误/空态、增量刷新；生命周期幂等，离页停止轮询，不能重复监听或重复发送。
- 验证：多主体/多团队隔离、并发发送、幂等冲突、游标、重启后权限与消息读回、真实浏览器发送并刷新读取。

## 四、Provider tokens/s：只报告有依据的度量

- 必须在实际模型请求链采集上游返回的输出 token 数和单调时钟测量的时间；无 usage 时返回 unavailable/null，不以字数、字节或固定常数估 token。
- 明确区分“端到端输出 token/s”（包含网络/首 token 等待）和流式解码速度；没有首/末 token 时间证据时不得称为解码吞吐。
- 可在已有 chat 响应中新增 metrics 并向 agents 页读数接线；若新增显式测量端点，必须用户点击触发且标明可能产生真实模型费用，不在页面加载后台反复生成计费请求。
- 对 NaN、无穷、负数、布尔伪数字、零耗时、缺失/非标准usage、上游失败均有明确语义；无失败伪读数、不缓存跨Provider错误归属。
- 保留现有连通性/latency能力，但延迟不是吞吐的替代。
- 验证：受控可计时上游验证公式/边界/失败；真实配置缺失如实降级；最终报告区分代码路径验证与真实上游验收。

## 五、验收不得缩减

三项均需要：冻结契约 → 实现 → 可执行测试 → 前端真实路径 → 故障/权限验证 → 独立审核。不能只让旧静态测试变绿、只替换“未接入”文字、只通过探针重分类或仅新增按钮占位。

## 六、协议与依赖待核实项

- 本轮已尝试用网络工具检索并打开 OpenAI 官方视频文档，但未返回可引用正文。因此不将该尝试当作协议已核实证据，实施负责人必须通过可读取的官方页面/API文档或用户提供的契约核对请求格式与状态语义。
- 候选官方资料定位地址（仅线索，不是冻结契约）：`https://developers.openai.com/api/docs/guides/video-generation`。不能据未核实记忆假定所有 Provider 视频协议相同、账户可用或默认模型/时长支持。
