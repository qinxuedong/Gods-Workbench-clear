# 视频页生产上下文选择补充方案（待审核）

## 发现
主代理真实Chrome测试以合法HTTP创建项目、画布拓扑及携带production_context的流水线，然后实际页面点击生成、预览、下载与FFmpeg合并导出通过。测试未绕过后端项目ACL/画布/entity校验。

但影视工坊的普通“创建分集”请求只有project_id/title等，没有production_context；阶段start也不补canvas/entity。因此上述通过不代表所有普通UI创建路径已闭环，不能宣称视频功能整体完成。

## 最小方案
- 在视频生成控制区增加“目标画布/实体”选择，读取已有GET /api/canvases?project_id=...及GET /api/canvases/{canvas_id}真实拓扑，不自行编造ID，不新增平行画布体系。
- 选择仅保存为当前流水线的本地用户偏好；每次新提交前重新读回画布及实体仍属于项目。后端继续最终校验ACL/项目/画布/实体，不以本地偏好作为授权。
- 缺少画布或实体时明确禁用生成/导出并提示先在项目画布中创建节点；不后台替用户创建、改写拓扑。不动已有生成请求的持久幂等payload，恢复仍使用原关联。
- 已有流水线production_context作为初始选择；仅当用户显式改选才覆盖。清空/失效不悄悄选第一个节点。
- 已生成素材仅用于同项目合并；切换画布实体影响新导出的追踪关联，不修改已有任务归属。
- 浏览器回归改为创建无production_context的正常流水线，实际操作选择控件后生成/下载/导出；另验证无上下文禁用、切换/刷新偏好和已删实体被后端拒绝。

此方案不新增自动收费行为；只有用户点击生成才创建远端任务。尚待独立审核，未实施选择器。
